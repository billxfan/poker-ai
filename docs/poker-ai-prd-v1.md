## 一、产品概述

### 1.1 产品定位

一款**纯本地离线运行**的iOS德州扑克AI训练工具，提供5个风格迥异、具备**统计数据驱动进化能力**的AI对手，100%模拟线下德扑的信息边界与博弈逻辑，帮助玩家在无网络、无真人风险的环境下打磨牌技。

### 1.2 核心目标

- ✅ 实现标准无限注德州扑克完整规则与流程
- ✅ 打造5种差异化AI打法风格，覆盖真实牌桌常见玩家类型
- ✅ 构建基于规则引擎 + 统计数据的本地AI进化系统（AI仅能使用自身可见信息）
- ✅ 适配iOS触控交互与横屏游戏体验
- ✅ 支持iCloud本地数据同步，多设备无缝切换
- ✅ 完全符合App Store审核规范，无任何涉赌风险

### 1.3 目标用户

- 德扑入门玩家：学习基础规则与常见打法
- 进阶玩家：训练读牌能力、对抗不同风格对手
- 德扑爱好者：休闲娱乐，避免真人对局的社交与资金风险

## 三、功能详细设计

### 3.1 游戏核心系统（P0）

#### 3.1.1 标准无限注德州扑克规则

- **牌型大小**：皇家同花顺 > 同花顺 > 四条 > 葫芦 > 同花 > 顺子 > 三条 > 两对 > 一对 > 高牌
- **游戏流程**：
  1. 盲注阶段：小盲、大盲自动下注
  2. 底牌阶段：每人发2张底牌，从大盲下家开始依次行动（弃牌/跟注/加注）
  3. 翻牌阶段：发3张公共牌，从小盲开始依次行动
  4. 转牌阶段：发第4张公共牌，行动顺序同上
  5. 河牌阶段：发第5张公共牌，行动顺序同上
  6. 摊牌阶段：剩余玩家亮牌，牌型最大者赢得底池
- **下注规则**：最小加注额=上一次加注额；支持全押（All-in）；支持多边池计算
- **座位与盲注轮换**：每局结束后按钮位顺时针移动，盲注随之轮换
- **淘汰机制**：玩家筹码为0时自动淘汰，剩余AI继续对战，直到决出最终赢家

#### 3.1.2 游戏房间创建

- 可配置参数：
  - 初始筹码：默认10000，范围1000-100000
  - 初始小盲注：默认50，大盲注=2×小盲注
  - 盲注上涨间隔：默认30分钟，支持10/15/20/30/45/60分钟及"关闭"选项
  - 局数限制：默认无限制，支持设置最大局数
- 快速开始：使用默认参数一键创建房间
- 保存房间：支持保存当前游戏状态，下次打开继续游戏
- 多存档管理：支持创建、重命名、删除最多5个独立存档

#### 3.1.3 规则教程系统

- 内置图文版德扑基础规则教程
- 牌型大小速查表
- 常见术语解释
- 支持在游戏中随时调出查看

### 3.2 AI对手系统（核心中的核心，P0）

#### 3.2.1 5种基础AI风格定义

| AI编号 | 风格名称 | 入池率 | 翻牌前加注率 | 核心特征 |
|--------|----------|--------|--------------|----------|
| AI-1 | 紧凶型（TAG） | 15%-20% | 60%-70% | 只玩强起手牌；入池后攻击性强；很少跟注；几乎从不诈唬 |
| AI-2 | 松凶型（LAG） | 35%-45% | 50%-60% | 玩大量边缘牌；频繁加注诈唬；喜欢用听牌半诈唬；翻牌后持续下注频率高 |
| AI-3 | 紧弱型（TP） | 12%-18% | 20%-30% | 只玩顶级起手牌；几乎从不诈唬；有牌就跟注，很少加注；容易被诈唬弃牌 |
| AI-4 | 松弱型（LP） | 30%-40% | 10%-20% | 玩很多弱牌；几乎从不加注；喜欢跟注到摊牌；是主要的输家类型 |
| AI-5 | 平衡型 | 22%-28% | 40%-50% | 混合强牌与诈唬；根据位置调整入池范围；会根据对手风格调整自己的打法 |

#### 3.2.2 基于规则引擎 + 统计数据的本地进化机制

**核心原则**：AI只能使用**自己亲眼看到的信息**进行决策和学习，绝对禁止访问其他玩家的底牌或未来的公共牌。

**AI可观测信息集**：
1. 自己的2张底牌
2. 所有已发出的公共牌
3. 本局所有玩家的每一轮下注动作（弃牌/跟注/加注金额/全押）
4. 本局所有玩家的筹码变化
5. 历史所有摊牌局中，其他玩家亮出的底牌
6. 历史所有玩家的动作频率统计（入池率、加注率、弃牌率等）

**技术实现**：

采用**规则引擎 + 统计数据驱动**的混合架构，不依赖神经网络训练：

1. **规则引擎层**：
   - 每种AI风格维护一套决策规则（起手牌范围、加注频率、跟注阈值等）
   - 规则参数（紧松度、凶弱度）可动态调整
   - 决策延迟 < 50ms，完全满足实时游戏需求

2. **统计学习层**（模拟"进化"）：
   - 记录每局所有玩家的动作到 SQLite 数据库
   - 周期性（每10局）分析玩家动作频率变化
   - AI根据分析结果调整自身规则参数：
     - 若发现玩家频繁诈唬 → 提高跟注频率
     - 若发现玩家紧弱 → 提高诈唬频率
     - 若发现玩家频繁弃牌 → 提高持续下注频率
   - **这不是真正的机器学习**，而是基于规则的统计适应，规避了Core ML在iOS上无法训练的问题

3. **每局结算后更新统计**：
   - 记录本局每个玩家的动作（弃牌/跟注/加注/全押）
   - 记录摊牌局的牌型与赢家
   - 更新玩家的累计统计数据

**"AI进化"的表现**：

| 阶段 | 行为变化 |
|------|----------|
| 初期（0-50局）| 严格遵循预设风格的决策概率 |
| 中期（50-200局）| 开始识别玩家的明显漏洞（如玩家频繁诈唬，AI会增加跟注频率） |
| 后期（200局+）| 形成针对当前玩家的个性化打法 |

**注意**：V1阶段的"学习"本质上是统计数据的积累和规则参数的微调，不涉及神经网络权重更新。这样做的好处是：
- 决策延迟可预测（< 100ms）
- 无需Core ML训练支持
- 行为可解释（可查看AI当前参数）
- 开发成本可控

## 五、技术架构设计

### 5.1 整体架构

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   SwiftUI界面   │    │   游戏引擎层    │    │    AI引擎层     │
│   （视图层）    │◄───┤ （游戏逻辑）    │◄───┤ （规则引擎）    │
└─────────────────┘    └─────────────────┘    └─────────────────┘
        │                      │                      │
        └──────────────────────┼──────────────────────┘
                               │
                      ┌─────────────────┐
                      │  本地数据层     │
                      │  （SQLite/GRDB）│
                      └─────────────────┘
                               │
                      ┌─────────────────┐
                      │  iCloud同步层   │
                      │  （CloudKit）    │
                      └─────────────────┘
```

### 5.2 技术栈选择

| 类别 | 选择 | 理由 |
|------|------|------|
| 开发语言 | Swift 5.9 | iOS 16+ 标准 |
| UI框架 | SwiftUI | iOS 16+ 标配，声明式UI开发效率高 |
| 游戏引擎 | 自定义轻量级德扑游戏引擎 | 纯Swift实现，无第三方依赖 |
| AI引擎 | **规则引擎 + 统计数据** | V1不采用Core ML训练，规避iOS无法训练的限制；使用决策树+概率分布模拟5种风格 |
| 本地数据库 | **SQLite（GRDB）** | 轻量、简单、App Store无风险；优于Core Data的重量级 |
| 云同步 | CloudKit | iCloud数据同步唯一选择 |
| 图表库 | Swift Charts | iOS 16+原生图表，完全够用 |
| 第三方UI | DGCharts（原Charts） | 可选，用于更丰富的扑克桌风格数据可视化 |

**为什么不使用 Core ML 训练？**
- iOS 设备上的 ANE（Apple Neural Engine）**不支持训练**，只支持推理
- 即使是 CPU/GPU 训练，5000 局经验回放池的梯度下降会导致决策延迟远超 500ms
- Core ML 的 `.mlmodel` 文件本质上是**推理模型**，无法在设备上更新权重
- 规则引擎 + 统计数据的方案在 V1 阶段完全满足需求，且行为可解释

### 5.3 数据存储设计（SQLite/GRDB）

- **游戏配置表**：存储用户的游戏设置与AI参数
- **玩家数据表**：存储玩家的历史统计数据
- **AI数据表**：存储每个AI的统计数据与规则参数
- **历史牌局表**：存储每局的完整信息（玩家动作、公共牌、底牌、结算结果）
- **存档表**：存储多个独立存档的信息
- **iCloud同步**：所有数据表均支持CloudKit同步

### 5.4 AI决策架构

```
┌─────────────────────────────────────────────────────────────┐
│                        AI决策流程                          │
├─────────────────────────────────────────────────────────────┤
│  1. 获取可观测信息（自己的底牌 + 公共牌 + 历史动作）       │
│                          ↓                                  │
│  2. 根据当前风格 + 规则参数，计算各动作概率                 │
│     - 弃牌概率 = f(牌力, 位置, 紧松度)                     │
│     - 跟注概率 = f(牌力, 底池赔率, 凶弱度)                 │
│     - 加注概率 = f(牌力, 位置, 玩家特征, 凶弱度)           │
│                          ↓                                  │
│  3. ε-greedy 探索：                                        │
│     - 概率(1-ε)：选择最高概率动作                          │
│     - 概率(ε)：随机选择动作（模拟真人不可预测性）          │
│                          ↓                                  │
│  4. 输出决策（弃牌/跟注/加注/全押）                       │
└─────────────────────────────────────────────────────────────┘
```

**每局结束后的统计更新**：
```
每局结束后：
  1. 记录本局所有动作到历史表
  2. 更新AI统计数据库（入池率、加注率、弃牌率等）
  3. 每10局：AI分析玩家统计数据 → 调整自身规则参数
```

## 六、交互设计（iOS专属）

### 6.1 整体设计原则

- 优先支持横屏模式，提供沉浸式游戏体验
- 操作按钮足够大（最小44×44pt），适合手指点击
- 简化界面元素，突出牌桌与核心操作
- 遵循iOS设计规范，使用原生组件与交互方式

## 七、测试计划

- 游戏规则测试：验证所有德扑规则的正确性（牌型大小、下注规则、边池计算等）

  - 固定玩家打法，测试AI在100局、200局后的胜率变化
  - 验证AI是否能识别并利用玩家的明显漏洞
- 数据统计测试：验证所有统计指标的计算准确性
- 复盘功能测试：验证历史牌局的回放与数据正确性
- iCloud同步测试：验证多设备之间的数据同步功能
- 后台运行测试：验证游戏进入后台与恢复的正确性

### 7.2 性能测试

- 单局游戏响应时间：<100ms
- AI决策时间：<50ms（规则引擎，毫秒级响应）
- 内存占用：<200MB
- 1000局游戏后的数据存储大小：<30MB
- 电池续航：连续游戏1小时，电池消耗<20%

### 7.3 合规测试

- 验证所有涉及筹码的地方都标注了"虚拟训练积分"
- 验证应用无任何充值、内购、提现功能
- 验证应用无任何社交、分享、排行榜功能
- 验证应用无任何网络请求（除iCloud同步外）
- 验证应用内无任何与赌博相关的词汇或图像
